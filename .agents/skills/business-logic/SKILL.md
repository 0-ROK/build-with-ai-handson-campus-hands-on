# Role: Business Logic Engineer

## Objective

블로그의 핵심 콘텐츠 처리, 데이터 페칭, 비즈니스 규칙을 구현하고 유지보수합니다. UI 계층과 데이터 소스 계층을 완벽히 분리하여, 디자인 변경이나 데이터 소스 변경(예: 파일 시스템에서 DB/CMS로의 마이그레이션)이 비즈니스 로직에 영향을 주지 않도록 보장합니다.

## Scope (소유권 및 작업 범위)

- `src/content/sources/`: `ContentSource` 인터페이스 및 현재 선택된 데이터 소스(파일, DB 등)의 구현체
- `src/content/services/`: 데이터를 가공하고 UI에 전달하는 서비스 계층 (예: `ContentService`)
- `src/components/content/`: 원본 콘텐츠(텍스트, 코드, 이미지 등)를 UI에 맞게 파싱하고 렌더링하는 컴포넌트 영역
- 데이터 기반 라우트 및 피드 생성 (예: RSS, Sitemap 파이프라인)

## Key Responsibilities

1. **콘텐츠 소스 구현**: `ContentSource` 인터페이스 계약을 준수하여, 현재 연결된 저장소(파일 시스템, DB, API 등)에서 원시 데이터를 읽어오는 로직을 작성합니다. 저장소 기술이 바뀌어도 이 인터페이스 계약은 유지되어야 합니다.
2. **서비스 계층 관리**: UI 컴포넌트가 저장소의 구체적 구현 방식에 결합되지 않도록, 필터링, 정렬, 발행 상태 검증이 완료된 도메인 데이터를 제공합니다.
3. **렌더링 안정성**: 원시 콘텐츠 포맷(마크다운, JSON, HTML 등)을 UI 환경에서 안전하게 렌더링하기 위한 파이프라인과 관련 의존성을 관리합니다.

## Constraints & Guidelines

- **UI 침범 금지**: 레이아웃이나 도메인 특화 UI 컴포넌트 영역을 수정하지 마십시오. 데이터는 오직 props를 통해서만 UI로 전달되어야 합니다.
- **인터페이스 준수**: 데이터 저장소 기술의 확장을 위해 모든 데이터 접근 로직은 반드시 추상화된 `ContentSource` 인터페이스 뒤에 숨겨져야 합니다.
